Angular y Flask, paso a paso

Dos proyectos pequeños pero completos, explicados concepto por concepto: un buscador de libros con Angular y una API de biblioteca con Flask. Todo el código se puede copiar y reutilizar.

Frontend Buscador de libros Angular 22, componentes standalone, signals, formularios reactivos y RxJS contra la API de Open Library. Backend API de biblioteca Flask 3, PostgreSQL, SQLAlchemy 2, Alembic y pytest. Autores, libros, socios y préstamos en 3 capas.

Cómo leer esta guía

  1. Primero el concepto, después el código. Cada sección explica una idea en pocas líneas y luego muestra dónde aparece en el proyecto.
  2. Copia sin miedo. Todos los bloques tienen un botón Copiar. El código de la sección "Código completo" es exactamente el de los proyectos.
  3. Haz el tuyo. Al final de cada parte hay una plantilla para crear un proyecto parecido (otra API, otra tabla).
Consejo para estudiarEscribe el código a mano la primera vez, aunque lo tengas para copiar. Cuando algo no funcione, compara con el bloque de la guía.

Parte 1 · Angular

Buscador de libros

Una sola pantalla: escribes en un campo y aparecen libros de Open Library. Parece simple, pero resuelve los problemas reales de cualquier buscador: no saturar la API, cancelar búsquedas viejas, mostrar "cargando" y errores.

Qué hace exactamente

  • No busca hasta que escribas al menos 3 letras.
  • Espera 300 ms después de la última tecla (no hace una petición por cada letra).
  • Si escribes algo nuevo mientras la búsqueda anterior sigue en camino, la cancela.
  • Muestra Buscando…, la cantidad de resultados, "Sin resultados" o un mensaje de error.
  • Si falla la red, el buscador sigue funcionando en la siguiente búsqueda.

Crear el proyecto#

Desde cero, con el CLI de Angular. Angular 17+ crea componentes standalone por defecto (sin NgModule).

npm install -g @angular/cli
ng new buscador --style=css --ssr=false   # responde "No" a zoneless si pregunta y no lo conoces
cd buscador
ng generate service libros/libros          # crea libros.service.ts
ng generate component libros/buscador      # crea buscador.ts / .html / .css
ng serve                                   # http://localhost:4200

Para correr el proyecto ya hecho:

cd angular-buscador
npm install
ng test --watch=false   # 5 tests en verde
ng serve

Regla prácticaAgrupa por funcionalidad (libros/, usuarios/), no por tipo de archivo (components/, services/). Así todo lo de "libros" está junto.

Componentes standalone#

Un componente es una pieza de pantalla: una clase TypeScript (lógica) + una plantilla HTML (vista) + CSS. "Standalone" significa que el componente declara él mismo lo que usa en imports, sin módulos.

@Component({
  selector: 'app-buscador',            // cómo se usa en HTML: <app-buscador />
  imports: [ReactiveFormsModule],      // lo que la plantilla necesita ([formControl])
  templateUrl: './buscador.html',
  styleUrl: './buscador.css',
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class Buscador { /* ... */ }

OnPush le dice a Angular: "vuelve a pintar este componente solo cuando cambie algo que yo uso" (un signal, un input, un evento). Con signals es la opción natural y hace la app más rápida.

El componente raíz solo coloca al buscador, y main.ts arranca todo:

// main.ts
bootstrapApplication(App, appConfig).catch((err) => console.error(err));

Signals: el estado de la pantalla#

Un signal es una caja con un valor que avisa cuando cambia. La plantilla lo lee llamándolo como función: libros(). Cuando haces .set(), Angular repinta lo que dependa de él.

readonly libros = signal<Libro[]>([]);          // estado: lista
readonly cargando = signal(false);                // estado: ¿esperando respuesta?
readonly error = signal<string | null>(null);     // estado: mensaje de error
readonly total = computed(() => this.libros().length); // derivado: se recalcula solo

this.cargando.set(true);     // escribir
this.libros();               // leer
this.total();                // leer un computed (no se puede hacer .set)
FunciónQué esCuándo usarla
signal(v)Valor que puedes cambiarEstado propio: lista, cargando, error, filtros
computed(fn)Valor calculado a partir de otros signalsTotales, listas filtradas, textos derivados
.set(v) / .update(fn)Cambiar el valorcontador.update(n => n + 1)
¿Signals o Observables?Signals para estado (lo que la pantalla muestra ahora). Observables (RxJS) para eventos en el tiempo (teclas, peticiones HTTP). Este proyecto usa los dos: RxJS procesa lo que escribes y el resultado final se guarda en signals.

Servicios e inyección de dependencias#

Un servicio es una clase para la lógica que no es de pantalla: llamar APIs, guardar datos compartidos. El componente no hace new LibrosService(); se lo pide a Angular con inject().

@Injectable({ providedIn: 'root' })   // una sola instancia para toda la app
export class LibrosService {
  private readonly http = inject(HttpClient);
}

export class Buscador {
  private readonly librosService = inject(LibrosService);
}

¿Por qué no new? Porque en los tests Angular puede darte una versión falsa (por ejemplo un HttpClient de prueba) sin tocar el componente.

HttpClient solo existe si lo registras una vez en app.config.ts:

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners(), provideHttpClient()],
};

HttpClient y Observables#

http.get() no hace la petición en el momento: devuelve un Observable, una "receta" que se ejecuta cuando alguien se suscribe. Con .pipe() le encadenas transformaciones.

buscar(texto: string): Observable<Libro[]> {
  const params = new HttpParams().set('q', texto).set('limit', 10);
  // GET https://openlibrary.org/search.json?q=borges&limit=10
  return this.http.get<RespuestaBusqueda>(this.url, { params }).pipe(
    map((respuesta) => respuesta.docs.map(/* convertir cada doc en Libro */)),
  );
}
Usa HttpParamsEn lugar de armar la URL a mano ('?q=' + texto), HttpParams codifica espacios, tildes y símbolos por ti.

Modelo de la API vs. modelo de la app#

La API responde con nombres en inglés y campos que pueden faltar. En vez de esparcir doc.author_name?.[0] por toda la app, el servicio traduce la respuesta a un tipo propio, limpio y sin opcionales.

La API devuelve (no lo controlas)Tu app usa (lo controlas)
key: stringid: string
title: stringtitulo: string
author_name?: string[]autores: string[] (vacío si no hay)
first_publish_year?: numberanio: number | null
respuesta.docs.map((doc) => ({
  id: doc.key,
  titulo: doc.title,
  autores: doc.author_name ?? [],          // ?? = "si es null/undefined usa esto"
  anio: doc.first_publish_year ?? null,
}))

Ventaja: si mañana cambias de API, solo tocas el servicio. El componente y la plantilla no se enteran.

Formularios reactivos#

Un FormControl representa un campo. Lo interesante es valueChanges: un Observable que emite cada vez que el usuario escribe. Eso es lo que conectamos a RxJS.

readonly busqueda = new FormControl('', { nonNullable: true }); // siempre string, nunca null
<input type="search" [formControl]="busqueda" placeholder="Escribe al menos 3 letras" />

Para que [formControl] funcione, el componente importa ReactiveFormsModule.

La tubería RxJS, operador por operador#

Esta es la parte central del proyecto. Cada tecla entra por arriba y pasa por estos "filtros" en orden:

this.busqueda.valueChanges
  .pipe(
    map((texto) => texto.trim()),          // 1. quita espacios
    debounceTime(300),                      // 2. espera 300 ms de silencio
    distinctUntilChanged(),                 // 3. ignora si es igual al anterior
    filter((texto) => texto.length >= 3),   // 4. mínimo 3 letras
    tap(() => {                             // 5. efecto: mostrar "cargando"
      this.cargando.set(true);
      this.error.set(null);
    }),
    switchMap((texto) =>                    // 6. pide a la API y CANCELA la anterior
      this.librosService.buscar(texto).pipe(
        catchError(() => {                  // 7. si falla, mensaje y lista vacía
          this.error.set('No se pudo conectar. Revisa tu conexión e intenta de nuevo.');
          return of([]);
        }),
      ),
    ),
    takeUntilDestroyed(),                   // 8. se desuscribe al destruir el componente
  )
  .subscribe((libros) => {
    this.libros.set(libros);
    this.cargando.set(false);
  });
OperadorEn una fraseSin él…
mapTransforma cada valor" borges " y "borges" serían búsquedas distintas
debounceTime(300)Deja pasar el valor solo si hubo 300 ms sin teclas"borges" = 6 peticiones
distinctUntilChangedBloquea valores repetidos seguidosBorrar y reescribir la misma letra repite la búsqueda
filterDeja pasar solo lo que cumple la condiciónBuscarías con 1 letra (miles de resultados)
tapHace algo "al costado" sin cambiar el valorNo habría estado de carga
switchMapCambia a un nuevo Observable y cancela el anteriorUna respuesta vieja y lenta podría pisar a la nueva
catchErrorAtrapa el error y devuelve un valor de reemplazoUn error mataría la tubería: no volvería a buscar nunca
takeUntilDestroyedCorta la suscripción cuando el componente muereFuga de memoria
Detalle importante: dónde va catchErrorEstá dentro del switchMap, en el Observable de la petición. Si lo pones afuera, al primer error la tubería principal se completa y el buscador deja de responder. Dentro, solo "muere" esa petición y la siguiente funciona.
¿Por qué switchMap y no mergeMap?

switchMap: solo importa la última búsqueda (buscadores, autocompletar).

mergeMap: todas en paralelo (subir varios archivos).

concatMap: una detrás de otra, en orden (guardar cambios en secuencia).

exhaustMap: ignora nuevas mientras hay una en curso (botón "Pagar" con doble clic).

Plantilla: @if y @for#

Angular 17+ trae control flow integrado. Reemplaza a *ngIf y *ngFor y no necesita importar nada.

@if (cargando()) {
  <p>Buscando…</p>
} @else if (error()) {
  <p class="error" role="alert">{{ error() }}</p>
} @else if (total() > 0) {
  <ul>
    @for (libro of libros(); track libro.id) {
      <li>{{ libro.titulo }} — {{ libro.anio ?? 'Sin año' }}</li>
    }
  </ul>
}
  • track libro.id es obligatorio: le dice a Angular cómo reconocer cada elemento para no recrear toda la lista.
  • El orden de los @if define la prioridad: primero "cargando", luego "error", luego resultados.
  • role="alert" hace que los lectores de pantalla anuncien el error.

Haz el tuyo: plantilla para cualquier API#

El mismo patrón sirve para buscar países, películas, usuarios de GitHub… Solo cambian 3 cosas: la URL, el tipo de la respuesta y la conversión. Ejemplo con la API pública de países:

  1. Genera la carpeta: ng g service paises/paises y ng g component paises/buscador-paises.
  2. Define los dos modelos (API y app) y la conversión en el servicio.
  3. Copia el componente del buscador cambiando el servicio y el tipo.
// paises/pais.model.ts
export interface PaisApi {            // lo que devuelve https://restcountries.com/v3.1/name/{texto}
  cca3: string;
  name: { common: string };
  capital?: string[];
  population: number;
}

export interface Pais {               // lo que usa tu app
  id: string;
  nombre: string;
  capital: string;
  poblacion: number;
}
// paises/paises.service.ts
import { HttpClient } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { Observable, map } from 'rxjs';

import { Pais, PaisApi } from './pais.model';

@Injectable({ providedIn: 'root' })
export class PaisesService {
  private readonly http = inject(HttpClient);

  buscar(texto: string): Observable<Pais[]> {
    const url = `https://restcountries.com/v3.1/name/${encodeURIComponent(texto)}`;
    return this.http.get<PaisApi[]>(url).pipe(
      map((paises) =>
        paises.map((p) => ({
          id: p.cca3,
          nombre: p.name.common,
          capital: p.capital?.[0] ?? 'Sin capital',
          poblacion: p.population,
        })),
      ),
    );
  }
}
// paises/buscador-paises.ts  (misma tubería que el buscador de libros)
import { ChangeDetectionStrategy, Component, inject, signal } from '@angular/core';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import { catchError, debounceTime, distinctUntilChanged, filter, map, of, switchMap, tap } from 'rxjs';

import { Pais } from './pais.model';
import { PaisesService } from './paises.service';

@Component({
  selector: 'app-buscador-paises',
  imports: [ReactiveFormsModule],
  template: `
    <input type="search" [formControl]="busqueda" placeholder="Busca un país" />
    @if (cargando()) { <p>Buscando…</p> }
    @else if (error()) { <p role="alert">{{ error() }}</p> }
    @else {
      <ul>
        @for (pais of paises(); track pais.id) {
          <li>{{ pais.nombre }} — {{ pais.capital }}</li>
        } @empty { <li>Sin resultados</li> }
      </ul>
    }
  `,
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class BuscadorPaises {
  private readonly servicio = inject(PaisesService);

  readonly busqueda = new FormControl('', { nonNullable: true });
  readonly paises = signal<Pais[]>([]);
  readonly cargando = signal(false);
  readonly error = signal<string | null>(null);

  constructor() {
    this.busqueda.valueChanges
      .pipe(
        map((t) => t.trim()),
        debounceTime(300),
        distinctUntilChanged(),
        filter((t) => t.length >= 2),
        tap(() => {
          this.cargando.set(true);
          this.error.set(null);
        }),
        switchMap((t) =>
          this.servicio.buscar(t).pipe(
            catchError(() => {
              this.error.set('No se encontró o no hay conexión.');
              return of([]);
            }),
          ),
        ),
        takeUntilDestroyed(),
      )
      .subscribe((paises) => {
        this.paises.set(paises);
        this.cargando.set(false);
      });
  }
}

@empty es un bloque opcional de @for que se muestra cuando la lista está vacía.

Errores comunes#

NullInjectorError: No provider for HttpClient

Falta provideHttpClient() en app.config.ts (o en los providers del test).

Can't bind to 'formControl' since it isn't a known property of 'input'

Falta ReactiveFormsModule en los imports del componente.

La pantalla no se actualiza

Con OnPush, si guardas datos en una variable normal (this.libros = [...]) Angular no se entera. Usa un signal y .set().

El buscador deja de funcionar después de un error

El catchError está fuera del switchMap. Muévelo adentro, sobre la petición.

Error de CORS en la consola

El servidor de la API no permite peticiones desde tu origen. Open Library sí lo permite; para tu propia API mira Conectar Angular con Flask.

En la plantilla sale "[object Object]" o la función entera

Olvidaste los paréntesis al leer el signal: es {{ total() }}, no {{ total }}.

Parte 2 · Flask

API REST de biblioteca

Una API JSON para gestionar autores, libros, socios y préstamos, con PostgreSQL. Lo importante no son las tablas, sino cómo se organiza el código para que crezca sin volverse un desorden: rutas, servicios y repositorios separados, errores claros y operaciones atómicas.

Reglas del negocio que implementa

  • Un libro siempre pertenece a un autor que existe; su año no puede ser futuro.
  • No se puede borrar un autor que tiene libros.
  • El email de un socio es único (sin importar mayúsculas).
  • Un libro prestado no se puede volver a prestar hasta que se devuelva.
  • Prestar = crear el préstamo y marcar el libro como no disponible. O pasan las dos cosas, o ninguna.

Instalar y arrancar#

# 1. PostgreSQL en Docker
docker run --name pg-biblioteca -e POSTGRES_USER=biblio -e POSTGRES_PASSWORD=biblio123 \
  -e POSTGRES_DB=biblioteca -p 5432:5432 -d postgres:16

# 2. Entorno virtual de Python
cd flask-biblioteca
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Dependencias y variables
pip install -r requirements.txt
cp .env.example .env

# 4. Crear las tablas (migraciones)

# 5. Tests y servidor
pytest -q                        # 16 passed
flask --app wsgi run --debug     # http://127.0.0.1:5000
Nunca subas .envEl .env tiene contraseñas y va en .gitignore. Al repositorio se sube .env.example con valores de ejemplo.

Arquitectura en 3 capas#

Cada petición atraviesa las capas en orden. Cada capa tiene un solo trabajo y solo habla con la de abajo.

CapaSabe de…NO sabe de…
routes/HTTP: leer JSON, query params, devolver código 201/204Reglas de negocio, SQL
services/Reglas: "un libro prestado no se presta", transaccionesHTTP (no devuelve 404, lanza NoEncontrado)
repositories/Cómo buscar y guardar en la base de datosReglas ni HTTP
models/Forma de las tablas y relacionesTodo lo demás
¿Para qué tanto?Para proyectos de una tabla es exagerado. Pero en cuanto aparecen reglas ("no prestar si…"), tenerlas en un solo lugar (el servicio) evita que se repitan o contradigan entre rutas. Y puedes probar un servicio sin levantar HTTP.

Estructura de carpetas#

flask-biblioteca/
├── wsgi.py                 ← punto de entrada: app = create_app()
├── config.py               ← Config (Postgres) y TestConfig (SQLite en memoria)
├── .env.example            ← DATABASE_URL de ejemplo
├── requirements.txt

├── app/
│   ├── __init__.py         ← create_app(): arma la app

│   ├── errors.py           ← excepción de negocio → código HTTP
│   ├── models/             ← Autor, Libro, Socio, Prestamo
│   ├── routes/             ← un blueprint por recurso + validacion.py
│   ├── services/           ← reglas de negocio + transaccion.py + excepciones.py
│   └── repositories/       ← consultas SQLAlchemy
└── tests/                  ← conftest.py (fixtures) + un archivo por recurso

App factory y configuración#

En vez de crear app = Flask(__name__) suelto, una función fabrica la app. Así los tests pueden crear una app con otra configuración (SQLite en memoria) sin tocar la de verdad.

  • db = SQLAlchemy() se crea en extensions.py sin app, y se conecta después con db.init_app(app). Así cualquier archivo puede importar db sin imports circulares.
  • pool_pre_ping comprueba que la conexión siga viva antes de usarla (evita errores si Postgres se reinició).
  • ensure_ascii = False hace que el JSON muestre "está" en vez de "está".

Modelos SQLAlchemy#

Un modelo es una clase Python que representa una tabla. Cada db.Column es una columna.

PiezaQué hace
nullable=FalseColumna obligatoria (NOT NULL)
unique=TrueNo puede repetirse (el email del socio)
db.ForeignKey("autores.id")Clave foránea: el valor debe existir en otra tabla
index=TrueÍndice para buscar rápido por esa columna
db.relationship(...)Acceso en Python: libro.autor, autor.libros (no crea columnas)
back_populatesConecta las dos direcciones de la relación
default=ahoraSe pasa la función (sin paréntesis) para que se llame en cada inserción
to_dict()Convierte el objeto a diccionario para devolverlo como JSON
default=ahora, no default=ahora()Con paréntesis, la fecha se calcularía una sola vez al arrancar el servidor y todos los préstamos tendrían la misma.

Migraciones con Alembic#

Una migración es un archivo que describe un cambio en la base de datos (crear tabla, agregar columna). Es como "git para el esquema": todos los entornos aplican los mismos pasos en el mismo orden.

flask --app wsgi db init                          # solo la primera vez: crea migrations/
flask --app wsgi db migrate -m "tablas iniciales" # compara modelos vs BD y genera el archivo
flask --app wsgi db upgrade                       # aplica las migraciones pendientes
flask --app wsgi db downgrade                     # deshace la última
Revisa siempre el archivo generadomigrate adivina los cambios comparando. Si renombras una columna, puede interpretarlo como "borrar y crear" y perder datos. Abre el archivo en migrations/versions/ antes del upgrade.

Rutas y blueprints#

Un blueprint agrupa las rutas de un recurso con un prefijo común. Las rutas son delgadas: leen la entrada, validan el formato, llaman al servicio y devuelven JSON con su código.

  • @bp.get(""), @bp.post("")… son atajos de @bp.route(..., methods=[...]).
  • <int:autor_id> convierte el trozo de URL a entero; si no es número, Flask responde 404 solo.
  • Devolver un dict lo convierte en JSON. La tupla (dict, 201) agrega el código.
  • return "", 204: éxito sin contenido (típico de DELETE).
Ver las demás rutas (libros, socios, préstamos)

El PATCH de libros solo cambia los campos que llegan: arma un diccionario cambios con lo enviado y el servicio aplica solo eso.

Hay dos tipos de validación y viven en lugares distintos:

Pregunta¿Llegó? ¿Es del tipo correcto? ¿Cabe en la columna?¿Tiene sentido para el negocio?

Servicios: las reglas del negocio#

Los servicios reciben datos ya validados en formato, aplican las reglas y lanzan excepciones de negocio cuando algo no se puede. No importan nada de Flask.

El servicio de socios muestra un patrón importante: chequear y además confiar en la BD.

¿Por qué dos chequeos del email?El primero (por_email) da un mensaje claro en el caso normal. Pero si dos peticiones llegan al mismo milisegundo, ambas pasan ese chequeo. La restricción UNIQUE de la base de datos es la que de verdad garantiza que no haya duplicados; capturamos su IntegrityError y respondemos 409 igual.

Funciones pequeñas con nombres del dominio (activos_de_socio, tiene_libros) que esconden el SQLAlchemy. Usan el estilo moderno de SQLAlchemy 2: select() + db.session.scalars().

Transacciones y bloqueos#

Una transacción agrupa varios cambios para que se guarden todos juntos o ninguno. Este helper lo hace con un with:

Prestar un libro hace dos cambios: crear el préstamo y marcar el libro como no disponible. Si el servidor se cae entre los dos, sin transacción quedaría un préstamo de un libro "disponible".

¿Qué es bloquear=True?

Genera SELECT … FOR UPDATE en PostgreSQL: bloquea la fila del libro hasta que termine la transacción. Si dos personas intentan prestar el mismo libro a la vez, la segunda espera, y cuando lee el libro ya ve disponible = False y recibe 409.

SQLite no lo soportaLos tests usan SQLite en memoria, donde FOR UPDATE se ignora. La atomicidad sí se prueba (ver test_atomicidad.py); el bloqueo real solo funciona en PostgreSQL.

Tests con pytest#

Las fixtures son funciones que preparan lo que un test necesita. pytest las inyecta por nombre: si un test pide libro_id, pytest crea primero el client, luego un autor y luego el libro.

Cada test arranca con una base de datos vacía (create_all / drop_all), así que no dependen entre sí.

El test más interesante: simula que el servidor falla justo después de guardar el préstamo y comprueba que no quedó nada a medias. monkeypatch reemplaza una función solo durante el test.

Ver test_libros.py y test_autores.py 
pytest -q                    # todo
pytest tests/test_libros.py  # un archivo
pytest -k prestar -v         # los que contienen "prestar" en el nombre

Agrega tu propio recurso#

Receta para sumar un recurso nuevo (o empezar otro proyecto con la misma estructura). Ejemplo: categorías de libros.

  1. Modelo en app/models/categoria.py y regístralo en app/models/__init__.py.
  2. Migración: flask --app wsgi db migrate -m "categorias", revisa el archivo y db upgrade.
  3. Repositorio con las consultas que necesites.
  4. Servicio con las reglas y with transaccion(): al guardar.
  5. Rutas en un blueprint y regístralo en create_app().
  6. Tests: una fixture en conftest.py y un test_categorias.py.
# app/models/categoria.py
from app.extensions import db


class Categoria(db.Model):
    __tablename__ = "categorias"

    id = db.Column(db.Integer, primary_key=True)
    nombre = db.Column(db.String(80), nullable=False, unique=True)

    def to_dict(self):
        return {"id": self.id, "nombre": self.nombre}
# app/repositories/categorias_repo.py
from sqlalchemy import select

from app.extensions import db
from app.models import Categoria


def listar():
    return db.session.scalars(select(Categoria).order_by(Categoria.nombre)).all()


def por_nombre(nombre):
    return db.session.scalar(select(Categoria).where(Categoria.nombre == nombre))


def agregar(categoria):
    db.session.add(categoria)
# app/services/categorias_service.py
from app.models import Categoria
from app.repositories import categorias_repo

from .excepciones import Conflicto
from .transaccion import transaccion


def listar():
    return categorias_repo.listar()


def crear(nombre):
    if categorias_repo.por_nombre(nombre) is not None:
        raise Conflicto("Ya existe esa categoría")
    categoria = Categoria(nombre=nombre)
    with transaccion():
        categorias_repo.agregar(categoria)
    return categoria
# app/routes/categorias.py
from flask import Blueprint

from app.services import categorias_service

from .validacion import leer_json, texto

bp = Blueprint("categorias", __name__, url_prefix="/categorias")


@bp.get("")
def listar():
    return {"items": [c.to_dict() for c in categorias_service.listar()]}


@bp.post("")
def crear():
    datos = leer_json()
    categoria = categorias_service.crear(nombre=texto(datos, "nombre", 80))
    return categoria.to_dict(), 201
# en app/__init__.py, dentro de create_app()
from .routes.categorias import bp as categorias_bp
app.register_blueprint(categorias_bp)

Errores comunes#

sqlalchemy.exc.ArgumentError: Expected string or URL object, got None

DATABASE_URL no está definida. Copia .env.example a .env y revisa que estés en la carpeta del proyecto.

connection refused en el puerto 5432

El contenedor de Postgres no está corriendo: docker start pg-biblioteca.

relation "autores" does not exist

Faltan las migraciones: flask --app wsgi db upgrade.

Could not locate a Flask application

Indica la app: flask --app wsgi run.

ModuleNotFoundError: No module named 'app' al correr pytest

Falta pythonpath = . en pytest.ini, o estás ejecutando pytest desde otra carpeta.

Mi tabla nueva no aparece en la migración

El modelo no está importado en app/models/__init__.py, así que Alembic no lo ve.

Siempre recibo 400 "Se esperaba un objeto JSON"

Falta la cabecera Content-Type: application/json en la petición.

Extra: conectar Angular con Flask#

Los dos proyectos son independientes, pero el siguiente paso natural es que un frontend Angular consuma la API Flask. Necesitas dos cosas:

1. Permitir CORS en Flask

El navegador bloquea peticiones de localhost:4200 a localhost:5000 salvo que el servidor lo autorice.

pip install flask-cors
# app/__init__.py, dentro de create_app()
from flask_cors import CORS
CORS(app, origins=["http://localhost:4200"])

2. Un servicio Angular para la API

// libros/biblioteca.service.ts
import { HttpClient, HttpParams } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { Observable, map } from 'rxjs';

export interface LibroApi {
  id: number;
  titulo: string;
  anio: number | null;
  disponible: boolean;
  autor_id: number;
}

@Injectable({ providedIn: 'root' })
export class BibliotecaService {
  private readonly http = inject(HttpClient);
  private readonly api = 'http://127.0.0.1:5000';

  libros(disponible?: boolean): Observable<LibroApi[]> {
    let params = new HttpParams();
    if (disponible !== undefined) params = params.set('disponible', disponible);
    return this.http
      .get<{ items: LibroApi[] }>(`${this.api}/libros`, { params })
      .pipe(map((r) => r.items));
  }

  prestar(libroId: number, socioId: number) {
    return this.http.post(`${this.api}/prestamos`, { libro_id: libroId, socio_id: socioId });
  }
}

Y para mostrar el mensaje que manda Flask cuando algo falla (por ejemplo 409 "El libro ya está prestado"):

import { HttpErrorResponse } from '@angular/common/http';

this.biblioteca.prestar(1, 1).subscribe({
  next: () => this.mensaje.set('Préstamo registrado'),
  error: (e: HttpErrorResponse) => this.mensaje.set(e.error?.error ?? 'Error inesperado'),
});
